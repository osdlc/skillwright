# @osdlc/tradecraft-wasm

The Tradecraft core, built to WebAssembly, for Node.js and Bun. skillwright
keeps agent skills as Markdown notes in a vault and builds them into the
layout each agent expects: Claude Code, Codex, Cursor and Pi. This package lets a JavaScript program do that without the
`skillwright` command-line tool: scan a vault, and render or check a
marketplace.

The package decides nothing itself. Parsing a note, resolving links, choosing
a target's layout and deciding whether an output file may be overwritten
all happen in the `tradecraft-core` Rust crate. This package passes JSON across
the boundary, turns a thrown core error into a typed one, and supplies the
filesystem the core is handed.

## Install

```sh
npm install @osdlc/tradecraft-wasm
```

`pnpm add @osdlc/tradecraft-wasm` and `yarn add @osdlc/tradecraft-wasm` work too.

The releases on npm were published from osdlc/osdlc and are behind this
source; to use this source, see [Building from source](#building-from-source).

ESM only. Node.js 22 or later, or Bun.

## Quick start

```ts
import { createNodeVfs, exportSkills } from '@osdlc/tradecraft-wasm'

const vfs = createNodeVfs()
const report = exportSkills(vfs, {
  vault_root: '/work/vault', // absolute: holds skillwright.md and marketplaces/
  marketplace: 'house', // marketplaces/house/, built into dist/house/
  mode: 'build', // 'check' reports drift and writes nothing
})
console.log(report.changed)
```

`marketplace` may be left out when the vault holds one marketplace. With
several and none named, the call throws, naming them. The core reads the
shared defaults and `build.harnesses` from `skillwright.md` itself, and
everything else from the vault's notes; a request carries no configuration.
`harnesses` narrows the root file's list to some of `'claude'`, `'codex'`,
`'cursor'` and `'pi'`. A harness the root file does not build is refused.

`buildVault(vfs, { vault_root })` builds every marketplace, and writes all of
them or none.

## API

Every call is synchronous. The first argument is a `Vfs`, the filesystem the
core reads and writes through. `createNodeVfs()` gives one over `node:fs`.

| Export                        | Does                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------- |
| `discoverComponents(vfs, request)` | Scans a vault's `marketplaces/` for components, and reports the notes it could not read. |
| `loadMarketplace(vfs, request)` | Loads one marketplace of the vault and writes nothing: its plugins, and each component's description, targets, harness blocks, calls and files. The rendered bodies do not cross. |
| `buildVault(vfs, request)`    | Renders every marketplace into its `<vault_root>/dist/<m>/`, and writes all of them or none. `mode: 'check'` reports drift and writes nothing. |
| `exportSkills(vfs, request)`  | Renders one marketplace into `<vault_root>/dist/<m>/`, one tree per agent. `mode: 'check'` reports drift and writes nothing. |
| `parseRootFile(text)`         | Reads the text of `skillwright.md`: its shared defaults, its `build` settings and a warning per unknown key. |
| `knownTargets()`              | The target names the core accepts: the `Target` type's four names.              |
| `createNodeVfs(options?)`     | The `Vfs` over `node:fs`.                                                       |
| `toCorePath`, `toHostPath`    | Convert a host path to the core's `/` form and back. They matter on Windows.    |

A call that the core refuses throws `CoreError`. Its `coreName` is the core's
error variant, such as `Refused` or `PathEscapesRoot`.

The request and report types are exported too. They are generated from the
Rust source, so they cannot drift from it.

## Behaviour

- All paths in a request are absolute. The core reads no current directory.
- A build writes only under `<vault_root>/dist/<m>/`, through the `Vfs` it is
  given. It never writes the vault's notes.
- Generated files carry the `Generated by skillwright` marker. Frontmatter
  keys carry no prefix.

## Runtimes and platforms

Node.js 22 or later, and Bun. The WebAssembly glue is built for Node.js: it
reads the `.wasm` file with `fs` from beside itself. So the package does not
load in a browser or through a bundler such as Vite. It has no native code.
The path conversion for Windows is tested against a stand-in filesystem on
every platform.

## Building from source

A checkout of the repository does not contain the built WebAssembly:
`pnpm run build:wasm` builds it from the Rust crates into `wasm/`. It needs
the Rust toolchain, `wasm-bindgen` and `wasm-opt`.
[CONTRIBUTING.md](./CONTRIBUTING.md#building-the-webassembly) lists the
versions.
