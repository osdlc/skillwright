# @osdlc/tradecraft-wasm

## Unreleased

### Breaking

- `publishSkill`, `adoptSkills`, `statusOf` and `publishableKinds` are removed, with their request and report types (`PublishRequest`, `PublishReport`, `AdoptRequest`, `AdoptReport`, `StatusRequest`, `PublishUnitStatus`, `PublishedFile`, `PublishReason`, `ReasonToken` and the types they use). Use `exportSkills`.
- `Target` is closed to `'claude' | 'codex' | 'cursor' | 'pi'`, with no open `string` tail. `knownTargets()` returns `Target[]`, and `ExportRequest` and `LoadRequest` type `harnesses` as `Target[]`.
- `exportSkills` writes `<vault_root>/dist/<m>/` through the given `Vfs`; there is no output-root field. `exportSkills` and `loadMarketplace` take the marketplace's folder name as `marketplace`, which is required on a vault of several: without it the call throws `Refused`, naming them.
- `rootFileConfig` is removed, with the `MarketplaceConfig` and `PluginOverrides` types. An `ExportRequest` or `LoadRequest` carries no configuration: the core reads the root file's shared defaults and `build.harnesses` from `skillwright.md` through the `Vfs`. A request that names `config` or `defaults` throws. `harnesses` narrows the root file's list; a harness it does not build throws `Refused` (`harness-not-built`). A marketplace's name, `owner` and every plugin field come only from the vault's notes.
- `buildVault(vfs, request)` is added, with `VaultRequest`, `VaultReport` and `MarketplaceReport`: every marketplace planned, then all written or none.
- `Plugin` and `Call` lose `prefixed_on`.
- `SkillId` gains `kind`: a call names a skill or a command.
- An unset identity field is absent instead of `null`: every component's `identity` in `discoverComponents`, so a skill's is `{}`, and the config `rootFileConfig` returns. `parseRootFile` already left unset fields out. Test for `undefined`, not `null`. ([#75](https://github.com/osdlc/skillwright/issues/75))
- The generated types change to match. `ContainerIdentity`'s fields are optional (`display_name?: string`, not `display_name: string | null`). `MarketplaceConfig` and `MarketplaceFields` list `keywords?` and `category?`, and `PluginOverrides` lists `owner?`, because they share the struct. Setting one of these is refused with an error naming the key and the level; it was never read. Their identity fields take `ContainerIdentity`'s doc comments, in its field order. The JSON stays flat: no `identity` key appears. ([#75](https://github.com/osdlc/skillwright/issues/75))

## 0.2.0

### Minor Changes

- d05e4ca: The core now writes the names of the `skillwright` CLI. The default frontmatter namespace is `sw` (`sw-kind`, `sw-targets`, …), the manifest is `.skillwright/manifest.json`, and generated files carry `Generated by skillwright`. Under the default namespace a note with a `tc-*` key is refused with its `sw-*` spelling, and a destination with only `.tradecraft/manifest.json` is refused with a rename hint.

## 0.1.0

### Minor Changes

- c9c911a: First release. The Tradecraft core, built to WebAssembly, for Node.js and Bun. It publishes a skill note to an agent's destination (`publishSkill`), reports what a publish would do (`statusOf`), scans a vault (`discoverComponents`), renders or checks a marketplace (`exportSkills`) and adopts published skills back into a vault (`adoptSkills`). `knownTargets()`, `canonicalTarget()`, `publishableKinds()` and `validateNamespace()` expose the core's vocabularies. The core decides everything: this package passes JSON across the boundary and turns a thrown core error into `CoreError`. `createNodeVfs()` gives the filesystem the core is handed, backed by `node:fs`, with the Windows path conversion. The request and report types are generated from the Rust source.
